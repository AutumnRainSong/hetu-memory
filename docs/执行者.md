## 二、岗位硬技能清单（面试照问）

### 存储引擎工程师

- [ ] SQLite WAL 写锁实战：busy_timeout、checkpoint 时机、长事务的相互影响
- [ ] 用条件更新（CAS）实现过不变量，不是"知道概念"
- [ ] HNSW 实战：内存放大、持久化格式、损坏重建
- [ ] **筛人题 A**：「备份恢复后如何保证被硬删除的数据不复活？」→ 答不出审计重放/墓碑机制 = 不适配
- [ ] **筛人题 B**：「两个进程同时对同一行条件写，链尾唯一性怎么保证？」→ 答"应用层锁" = 不适配，必须落到存储层

### 服务与协议工程师

- [ ] 实现/调试过 MCP server 或等价插件协议，能讲清 tool call 生命周期与 elicitation 语义
- [ ] 权限系统：能解释为什么 sensitivity 过滤在检索前而不是重排时（访问控制 ≠ 相关性排序）
- [ ] 有意图级鉴权经验（区分"调用什么工具"与"触发什么语义动作"）
- [ ] **筛人题 C**：「Proposal 等待用户确认期间，如何避免长期持有数据库锁？」→ 答"排队时开事务等" = 不适配，必须答两阶段（批准 ≠ 提交）+ 无长锁 + 存储层 CAS 终验

### 共同要求

- [ ] 表驱动测试实际使用经验（不是"会写单测"）
- [ ] 接受"测试不过不合并"硬门禁
- [ ] 入职前通读主规格 v1.4 与 continue_bro.md，能复述十条设计纪律中至少 6 条

## 三、文化守则（团队公约）

1. **矩阵即规格**：行为矩阵是唯一事实源；实现偏差 = bug，不是"优化"
2. **设计变更流程**：提案 → 用户/评审确认 → 文档先行 → 代码跟进；执行者不改设计文档
3. **承认偏差要快**：本设计史上被推翻的三项（导入重跑淘汰、created_at 当活跃时间、整节点冻结）当初都很优雅
4. **不炫技条款**：决策引擎用 if-chain 是明确的架构决策；警惕"顺手抽象"
5. **静默丢失过敏**：任何"数据可能无声消失/复活"的实现当场升级为缺陷

## 四、MVP 验收门禁（毕业考，缺一不验收）

一条真实框架 adapter（Claude Code 或 DSH）走通：

```
记住 → 跨会话召回 → 删除（Forget）→ 不再出现
→ 导出（洛书）→ Restore → Purge 过的内容不复活
```

- [ ] 行为矩阵 5×8 全组合表驱动测试通过
- [ ] 洛书 round-trip + 随机删节点 fuzz 通过
- [ ] Restore 与 Merge 独立测试通过
- [ ] Proposal 异常场景测试（等待/过期/重验/并发预留）通过
- [ ] 容量并发一致性测试通过
- [ ] 性能目标：Recall P95 ≤150ms / Persona 装配 P95 ≤10ms / 增量索引 ≤1s / 后台影响 ≤10%
- [ ] 权限泄漏专项 QA（200 条级）零失败
- [ ] RAW 背压压力测试：Digest 全挂+持续写入下零未归档 RAW 删除
- [ ] Purge 后五处残留断言（DB/边/FTS/HNSW/blob）全空 + 崩溃对账收敛
- [ ] 跨 Agent 隔离属性测试：Restore 与 Merge 权限判定结果一致
- [ ] 安全审计：无绕过写入闸门的写路径

## 五、协作方式

- **AI 结对用法**：实现每个矩阵格之前，先让 AI 从设计文档推导测试用例——推导不出来说明设计有歧义，先修设计再写代码
- **大师用法**：阶段末致命专项审查（第 6 轮模式的延续），平时不打扰；审查载体 = 仓库 Issue 留痕
- **用户用法**：哲学级取舍（命名、优先级、体验 vs 边界）由用户拍板；团队提供带代价和风险的选项
- **节奏**：阶段一末做设计符合性审查（对照 v1.4 逐节打勾），防实现漂移

## 六、一句话

> **1 名懂数据库底座的资深主程 + 1 名懂协议与权限的中高级工程师 + 持续在场的对抗性评审 + 一个被 continue_bro.md 和表驱动测试约束住的 AI 结对**，就是河图从 v1.4 走到 MVP 的最小可信团队。
