# 河图 HeTu · 研发组织与职责

> 基线：主规格 v1.4 收敛定稿 · 洛书 v0.3 · 2026-11-23 启动

## 一、角色与权责

| 角色 | 担任 | 核心责任 | 最终交付 |
|---|---|---|---|
| **产品负责人** | 用户（AutumnRainSong） | 产品方向、需求优先级、重大架构决策、产品语义最终裁定 | 产品验收与决策 |
| **项目交付负责人** | 当前员工 | 计划、任务分解、进度、风险、跨人员协调 | 项目计划与交付管理 |
| **技术负责人** | 存储主程（须经能力考核任命） | 架构、数据模型、技术方案、代码质量、设计决策记录 | 技术架构与核心实现 |
| **存储工程师** | 存储主程兼任 | SQLite/WAL/事务/CAS/Outbox/索引/归档/Purge Ledger | 存储引擎 |
| **服务工程师** | 服务岗 | API、MCP、权限、Recall、Proposal、洛书 | 服务层 |
| **QA/SDET** | QA 岗 | 测试策略、自动化测试、故障注入、独立质量验收（Stop-ship 权限） | 独立测试报告 |
| **DevOps（兼职 0.2-0.3）** | 待定 | CI、构建、部署、监控、发布 | 工程化流水线 |
| **外部架构评审** | 大师 | 阶段末专项审查（阶段一/二/三末） | 审查报告 |
| **AI 工程协作** | continue_bro.md 入职 | 测试生成、矩阵覆盖、fuzz、PR 审查、文档一致性 | 辅助产出（不担质量责任） |

## 二、关键规则

1. 每模块**唯一负责人**；跨层模块接口契约评审后才能开工
2. DB 写入只经统一写入闸门；CAS/链尾唯一性由存储层保障
3. 权限校验由服务端实施，不依赖 agent 自觉
4. 所有状态转换必须有行为矩阵测试；测试不过不合并
5. QA 拥有独立质量判定权与 Stop-ship 权限
6. 影响产品语义、删除承诺、权限边界的变更须产品负责人确认
7. 设计变更流程：提案 → 确认 → 文档先行 → 代码跟进

## 三、审查与升级路径

- 技术分歧：技术负责人裁决；涉及产品语义升级产品负责人
- 质量争议：QA 独立判定，可 Stop-ship
- 阶段出口：外部架构评审专项审查通过后方可进入下一阶段
